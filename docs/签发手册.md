# 签发手册（仅你自己看）

> **这份文档不要发给客户。** 里面有主密钥位置、账本路径、运营接口凭据。
> 客户看的版本是 [用户手册.md](用户手册.md)。

## 一、你手上有什么

四样东西，各管一件事，**丢哪个都补不回来**：

| # | 是什么 | 在哪 | 丢了会怎样 |
|---|---|---|---|
| 1 | **主密钥** | `~/.tdl-issuer.txt` | 现有客户照常能用，但**你再也签不出同族的新密钥**——续期、换机、新客户全部断掉 |
| 2 | **签名 keystore** | `~/.tdl-release.jks` + `~/.tdl-release.txt` | 老客户**无法覆盖升级**（签名不一致会被系统拒绝），只能卸载重装、数据全丢 |
| 3 | **账本** | `~/.tdl-license/registry.json` | 服务端不认所有已售密钥（`unknown_key`），需要重新登记 |
| 4 | **运营凭据** | `~/.tdl-license/admin.env` | 撤不了权、解不了绑；可重新生成并重启服务 |

**立刻做**：把 1、2、3 打包加密后放到离线介质（U 盘 / 加密网盘），别只留在这台机器的家目录。

```bash
tar czf ~/tdl-secrets-$(date +%Y%m%d).tgz \
  ~/.tdl-issuer.txt ~/.tdl-release.jks ~/.tdl-release.txt ~/.tdl-license/registry.json
# 然后用你惯用的方式加密，例如：
gpg -c ~/tdl-secrets-$(date +%Y%m%d).tgz && rm ~/tdl-secrets-$(date +%Y%m%d).tgz
```

## 二、卖一单的完整流程（5 步）

设 `TD=./tdl`（或 `~/go/bin/tdl`）。

### 步骤 1：客户报设备码

客户装好 APK 打开，激活页显示 8 位设备码，例如 `CT84B4MD`。
**让他截图发你**，避免手打出错（`0/O`、`1/I` 容易混，虽然程序会纠正，但别赌）。

### 步骤 2：签发密钥

**推荐用 TUI（省得背参数、自动记台账）：**

```bash
./scripts/license-tui.sh
```

菜单里选「1 签发新密钥」，依次填设备码、选时长、选强度、填备注，确认后直接出：

- 密钥（已自动复制到剪贴板）
- 给客户的话（整段可直接转发，[m] 复制）
- 台账自动记一条（时间 / 设备码 / 期限 / 序列号 / 备注）

`--check` 能反查：输入序列号就能从台账换回完整密钥并校验，不用翻记录找。

无人值守（批量、脚本里调）：

```bash
./scripts/license-tui.sh --gen --device CT84B4MD --days 365 --note "张三 微信zhang3"
```

---

**手动签发（等价，不想用 TUI 时）：**

```bash
DEV=CT84B4MD

# 一年期，绑这台设备（推荐）
KEY=$($TD license gen --key-file ~/.tdl-issuer.txt --device "$DEV" --days 365 | head -1)
echo "$KEY"
```

输出形如：

```
MF7TH6NK-222C8PKD-2TYRNSC3-THMCNGSF-2H5SPB6G
    序列号 7FQ2M9KD · 至 2027-10-30（365 天） · 绑定设备 CT84B4MD
```

**第一行才是密钥，第二行是给你自己看的备注，不要一起发出去。**

### 步骤 3：登记到服务端（漏了这步客户会看到「密钥不存在」）

> **用 TUI（`scripts/license-tui.sh`）的话这一步已经自动做了**，签发完会打印
> `✓ 已登记到授权服务器`；失败会红字警告并**不把密钥放进剪贴板**，避免你直接把一把
> 打不开的密钥发出去。手工补登记用 `scripts/license-tui.sh --admit <序列号>`，
> 查漏用 `scripts/license-tui.sh --pending`。
> 下面这些是**手工路径**，`--offline`/脚本化签发时用。

签发只要主密钥（可离线）；**登记要账本**，必须做：

```bash
TOK=$(sed -n 's/^ADMIN_TOKEN=//p' ~/.tdl-license/admin.env)

curl -s -X POST https://lic.emoe.eu.cc/v1/admit \
  -H "Authorization: Bearer $TOK" \
  -H 'Content-Type: application/json' \
  -d "{\"key\":\"$KEY\",\"kind\":\"short\",\"expiry_day\":365,\"note\":\"客户张三 微信xxx\"}"
```

返回 `{"ok":true,"code":"ok","entry":{...}}` 即成功。`note` 随便写，将来查账靠它认人。

> **token 在两个文件里，键名不同**：
> `~/.tdl-license/admin.env` 是 `ADMIN_TOKEN=`（运营用，短）；
> `~/.tdl-license/server.env` 是 `TDL_ADMIN_TOKEN=`（服务启动读的，systemd `EnvironmentFile`）。
> 两者都能过鉴权，但 `sed` 的前缀别写错，否则取到空字符串 → `unauthorized`。

> 为什么分两步：**能签名的只有你（私钥在你电脑），能放行的也只有你（账本在你服务器）。**
> 这样即使有人偷到 APK 里的校验串，伪造出一把「签名正确」的密钥，服务端也会拒（`unknown_key`）。

### 步骤 4：发给客户

只发这一行：

```
MF7TH6NK-222C8PKD-2TYRNSC3-THMCNGSF-2H5SPB6G
```

配一句：「激活页粘贴，点激活」。

### 步骤 5：确认

**这一步要分两个时间点看，别搞混：**

**① 你刚登记完（客户还没激活）** —— `device` 一定是空的，这是正常的：

```bash
curl -s -H "Authorization: Bearer $TOK" https://lic.emoe.eu.cc/v1/keys \
  | jq -r '.keys[] | select(.key=="'"$KEY"'") | "device=[\(.device)]  revoked=\(.revoked)"'

# device=[]  revoked=false        ← 登记成功，等客户激活
```

> 登记只把密钥录入账本，**设备是客户第一次激活时才绑定的**。
> 所以这个阶段 `device` 空不代表出错；只要这条能查出来、`revoked=false`，就是成功的。

**② 客户说「激活好了」之后** —— 这时才应该看到设备码：

```bash
# device=[CT84B4MD]  revoked=false  bound_at=2026-10-30T12:40:27Z
```

`bound_at` 有值 = 真的绑上了。如果客户说激活成功，而你这里 `device` 还是空 → 他多半只是
打开了 App 没提交，或者提交时带了空格。

**③ 想知道他最近还在不在用**：看 `last_seen`。App 每 12 小时心跳一次会刷新它。

## 三、签发参数

```bash
$TD license gen --key-file ~/.tdl-issuer.txt --device <设备码|any> <期限> [选项]
```

| 参数 | 说明 |
|---|---|
| `--device <8位码>` | 绑定这台设备。**换机即失效，必须找你重签**——最严，推荐 |
| `--device any` | 首次激活时自动绑那台机器。客户不用先报码，好卖，但 root 机器可以改文件换机 |
| `--days N` | 有效天数 |
| `--forever` | 永久密钥（与 `--days` 互斥） |
| `--strong` | Ed25519 强密钥（127 字符，只能粘贴，逆向也伪造不了） |
| `--count N` | 一次签 N 个（`--device any` 批量零售用） |

**常用组合**：

```bash
# 试用 7 天
$TD license gen --key-file ~/.tdl-issuer.txt --device "$DEV" --days 7

# 年费
$TD license gen --key-file ~/.tdl-issuer.txt --device "$DEV" --days 365

# 永久买断
$TD license gen --key-file ~/.tdl-issuer.txt --device "$DEV" --forever

# 高价值客户（防逆向）
$TD license gen --key-file ~/.tdl-issuer.txt --device "$DEV" --forever --strong

# 零售：先签 10 把不绑设备的，卖一把登记一把
$TD license gen --key-file ~/.tdl-issuer.txt --device any --days 30 --count 10
```

**短密钥 vs 强密钥，卖之前想清楚**：

| | 短（默认，40 字符） | 强（`--strong`，127 字符） |
|---|---|---|
| 客户能手打 | 能 | 只能粘贴 |
| 挡住什么 | 随手编、改字符、复制到别的机器 | 上面全部 + 从 APK 里挖出校验串后伪造 |
| 卖点 | 方便 | 贵 |

短密钥的校验串**在 APK 里**，理论上能被逆向挖出来自己造。拦住的是 99% 的人，不是专业逆向。
要真防，用 `--strong`——私钥永远只在你这台机器上。

## 四、日常运营

先设好两个变量，后面照抄：

```bash
TOK=$(sed -n 's/^ADMIN_TOKEN=//p' ~/.tdl-license/admin.env)
API=https://lic.emoe.eu.cc
TD=./tdl
```

| 场景 | 命令 |
|---|---|
| **查全部密钥** | `curl -s -H "Authorization: Bearer $TOK" $API/v1/keys \| jq` |
| **查单把** | `$TD license check "密钥" --key-file ~/.tdl-issuer.txt` |
| **续期** | 客户设备码不变 → 直接签新的、登记新的、发给他。旧的自然到期 |
| **换手机** | ① 先确认是他本人（问旧机设备码）② 解绑旧的：`curl -X POST -H "Authorization: Bearer $TOK" -d '{"key":"旧KEY"}' $API/v1/release` ③ 用新设备码签新的 |
| **退款 / 跑路** | `curl -X POST -H "Authorization: Bearer $TOK" -d '{"key":"KEY"}' $API/v1/revoke` → **下次心跳即失效**，最长 12 小时 |
| **他被锁在外面想立刻生效** | 撤销后让他杀进程重开 App，重启时就会核对一次 |
| **看盗用信号** | `/v1/keys` 里 `refusals > 0` 的，是有人拿同一把密钥反复激活第三台设备 |

**撤销不是删除**：密钥还在账本里，标记为 `revoked`。后悔了可以重新 `admit` 同一把。

## 五、撤销的生效机制（跟客户解释时用这个）

```
客户 App 每次启动 → 距上次成功核对 > 12 小时 → 向服务端要一次结论

服务端说 revoked / expired  → 清掉本地激活，回激活页
网络不通                     → 保留本地激活（断网不惩罚已付费客户）
```

所以：

- **撤销当天收敛**，不是秒级
- 客户断网也照常用 → 这是设计，不是漏洞
- 要更快就改 `--license-check` 间隔，代价是弱网客户启动变慢

## 六、构建发行版（注入开关）

**不注入 = 没有授权门**。这是给开发自测用的，绝不能发出去。

### Android

```bash
export TDL_LICENSE_MASTER_FILE=~/.tdl-issuer.txt
bash android/build-aar.sh                    # AAR 带校验串和公钥
# 再 gradle assembleRelease
```

### 桌面 / 服务端

```bash
FLAGS=$($TD license verifier --key-file ~/.tdl-issuer.txt | tr '\n' ' ')
go build -ldflags "-s -w $FLAGS" -o tdl .
```

### Docker

```bash
make licensed-docker TDL_LICENSE_MASTER_FILE=~/.tdl-issuer.txt \
  LICENSE_SERVER=https://lic.emoe.eu.cc
```

### 客户端接服务端

| 端 | 怎么接 |
|---|---|
| 手机 | 编译时 `-X github.com/iyear/tdl/archive.licenceServerDefault=https://lic.emoe.eu.cc`（已内置在 2.8.0+） |
| 命令行 | `tdl license activate --key <密钥> --server https://lic.emoe.eu.cc` |
| Docker | `tdl archive serve --license-server https://lic.emoe.eu.cc` |

## 七、服务运维

```bash
systemctl --user status tdl-license tdl-tunnel
systemctl --user restart tdl-license          # 改完配置重启
journalctl --user -u tdl-license -n 50
curl -s https://lic.emoe.eu.cc/healthz        # {"keys":N,"ok":true,...}
```

| 组件 | 位置 |
|---|---|
| 服务单元 | `~/.config/systemd/user/tdl-license.service` |
| 隧道单元 | `~/.config/systemd/user/tdl-tunnel.service` |
| 账本 | `~/.tdl-license/registry.json`（0600） |
| 凭据 | `~/.tdl-license/admin.env`、`server.env` |
| 公网入口 | `https://lic.emoe.eu.cc` → 隧道 → `127.0.0.1:8964` |

**开机自启**依赖 `loginctl enable-linger $USER`，已经设过。换机器要重设。

**手动起（调试用）**：

```bash
$TD license server \
  --db ~/.tdl-license/registry.json \
  --admin-token "$(openssl rand -hex 16)" \
  --addr 127.0.0.1:8964
```

## 八、客户报错 → 你查什么

| 客户看到 | 含义 | 你做什么 |
|---|---|---|
| 「密钥格式不对」 | 粘贴带了空格/换行，或少了分组 | 让他重新复制整行 |
| 「密钥不存在，请核实是提供者发的那一串」 | 服务端账本里没有 | 补 `admit` |
| 「密钥校验失败」 | 签名不对（改过字符 / 不是你的密钥） | 重发原密钥 |
| 「这个密钥是给另一台设备签发的」 | 设备码不匹配 | 核对设备码；换机就走 `release` + 重新签 |
| 「这个密钥已被禁用」 | 被你 `revoke` 了 | 想恢复就重新 `admit` |
| 「这个密钥已过期」 | 到期 | 续期 |
| 激活后过一阵又回激活页 | 心跳拿到 revoked/expired | 查 `/v1/keys` 该条状态 |
| 完全打不开、没有激活页 | 装的是**未注入**的构建 | 发注入版的 APK |

**本地激活文件**在 App 私有目录 `<filesDir>/archive/license/activation.json`，删掉它等于强制重新激活（客户自己操作需要 root，不用担心他乱删）。

## 九、红线（碰了就是给自己挖坑）

1. **主密钥永不外发。** 不进仓库、不进 APK、不发客户、不贴在聊天里。
   要给别人看构建参数，只给 `hmacKeyB64` / `pubKeyB64` 那两行。
2. **keystore 一旦发给客户就不能换签名。** 换了签名 → 设备码全变 → **所有客户都要重新激活**。
   要换就趁现在（还没发货）。
3. **`--device any` 不是技术防线。** root 机器改 `activation.json` 就能换机。
   真正一机一码就每单问设备码。
4. **每卖一把就 `admit` 一把。** 漏登记 = 客户用不了，你会收到「密钥不存在」的截图。
5. **账本要备份。** `registry.json` 里有所有已售密钥全文，丢了要挨个重新登记。
6. **构建前确认注入了。** 发出去一个没注入的包，等于送了一份无锁版。

## 十、快速检查表（每单 30 秒）

```
□ 设备码是客户截图来的（不是手打）
□ gen 出来的 KEY 只有第一行发出去
□ admit 返回 {"ok":true}
□ /v1/keys 里该条 device 已填、state=active
□ 只在聊天里发密钥，不发截图（防止被 OCR 存档到别处）
```
