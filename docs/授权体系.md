# 商业授权体系

给这个软件加一把锁：**没有你签发的密钥，客户用不了；一把密钥只能激活一台手机。**

---

## 一、它由什么组成

```
你的电脑                                   客户的手机
┌─────────────────────────┐                ┌──────────────────────┐
│ 主密钥 TDLSK1-…          │                │ App 内置：            │
│   ├─ 派生 HMAC 校验串     │  编译时注入 →   │   校验串（验短密钥）  │
│   └─ 派生 Ed25519 私钥    │                │   公钥（验强密钥）    │
│                          │                │                      │
│ tdl license gen          │  密钥（聊天发）→ │ 激活页输入 → 本地落盘 │
└─────────────────────────┘                └──────────────────────┘
```

没有服务器。密钥自带签名，App 离线就能判断真假——这是关键：你不需要为卖软件架一台授权服务器。

---

## 二、一次性配置（只做一次）

```bash
# 1. 生成主密钥。这是唯一需要保密的东西，丢了就再也签不出同族密钥。
./tdl license keygen --out ~/.tdl-issuer.txt
```

输出三样东西：

| 输出 | 用途 |
|---|---|
| `TDLSK1-…` | 主密钥，自己收好，**不进仓库、不发客户** |
| `-X …hmacKeyB64=…` | 编译时注入（短密钥校验） |
| `-X …pubKeyB64=…` | 编译时注入（强密钥校验） |

随时可以重新打印后两行：

```bash
./tdl license verifier --key-file ~/.tdl-issuer.txt
```

## 三、构建带授权的版本

**Android App：**

```bash
export TDL_LICENSE_MASTER_FILE=~/.tdl-issuer.txt
bash android/build-aar.sh
# 再打 APK（gradle assembleRelease）
```

**桌面 / 服务端：**

```bash
FLAGS=$(./tdl license verifier --key-file ~/.tdl-issuer.txt | tr '\n' ' ')
go build -ldflags "-s -w $FLAGS" -o tdl .
```

> 不注入任何东西时，构建出来的版本**没有授权门**——这是给开发和测试用的。发行版必须注入。

## 四、给客户签发密钥

客户第一次打开 App，激活页会显示一个 **8 位设备码**，例如 `7K3M9QX2`。让他发给你，然后：

```bash
# 绑定这台设备，有效期 30 天
./tdl license gen --key-file ~/.tdl-issuer.txt --device 7K3M9QX2 --days 30

# 永久密钥
./tdl license gen --key-file ~/.tdl-issuer.txt --device 7K3M9QX2 --forever

# 不绑设备（首次激活自动绑定那台机器）—— 不用先问客户要设备码
./tdl license gen --key-file ~/.tdl-issuer.txt --device any --days 7

# 批量（一次签 10 个）
./tdl license gen --key-file ~/.tdl-issuer.txt --device any --days 30 --count 10
```

输出：

```
P2NV18N5-222C8PKD-2TYRNSC3-THMCNGSF-2H5SPB6G
    序列号 CTBCYNN2 · 至 2026-11-29（30 天） · 绑定设备 YMPVKRTP
```

把第一行发给客户，他粘贴进激活框即可。

随时可以反查一个密钥：

```bash
./tdl license check "P2NV18N5-..." --key-file ~/.tdl-issuer.txt
```

## 五、"一个密钥只能解锁一台机器"是怎么保证的

| 场景 | 结果 |
|---|---|
| 密钥绑定设备 A，拿到设备 B 上激活 | **拒绝**（"这个密钥是给另一台设备签发的"） |
| 把 A 机的激活文件整个拷到 B 机 | **拒绝**（密钥内绑定 A 的码，与 B 不符） |
| 改系统时间回拨到到期前 | **拒绝**（本地记录只增不减，回拨超过 6 小时即判定异常） |
| 改激活文件里的到期日 | 无效（到期日写在签名里，改了签名就对不上） |
| 删 App 重装（绑定式密钥） | 设备码不变，可重新激活 |
| 删 App 重装（`--device any`） | 本地记录丢失，可重新激活到同一台机器 |

## 六、两种密钥格式，选一个

| | 短密钥（默认） | 强密钥（`--strong`） |
|---|---|---|
| 长度 | 40 字符 | 127 字符 |
| 能不能手打 | **能**（分组 8 位，O/I 自动纠正） | 只能粘贴 |
| 伪造难度 | 需要从二进制里挖出校验串 | 拿到整个二进制也伪造不了（私钥不在里面） |
| 适合 | 普通客户 | 高价值客户、会被逆向的场合 |

**短密钥的边界要说清楚**：它的校验串被编译进 App，理论上逆向能挖出来。拦住的是"随手编一个"和"拿别人密钥改字符"，不是专业逆向。

要真正防逆向，用 `--strong`——Ed25519 私钥永远只在你的电脑上，App 里只有公钥。

## 七、日常运维

| 客户问 | 你做什么 |
|---|---|
| "我换手机了" | 要旧机设备码确认是他，然后给新设备码签一个新的 |
| "密钥过期了" | 用同设备码签一个新的，旧的到期自动失效 |
| "我要永久版" | `--forever` |
| "密钥丢了" | 重新签一个（序列号会不同，旧的那个仍无法在别的机器用） |
| "激活页打不开" | 检查 App 是不是注入了授权（未注入的构建没有激活页） |
