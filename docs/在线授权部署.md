# 在线授权部署（含 Cloudflare Tunnel）

离线签名只能证明「密钥是我签的」，证明不了「这把密钥只用在一台设备上」——
客户端文件可以被复制，签名拦不住复制。把绑定关系放到服务端，复制就失去了意义。

这套服务补的就是那一半：

| 能力 | 离线签名 | + 在线服务 |
| --- | --- | --- |
| 密钥真伪 | ✅ | ✅ |
| 绑定设备码 | ✅（写死在密钥里，换机即废） | ✅（服务端账本，换机需运营放行） |
| `--device any` 首激绑定 | ❌ 可改文件换机 | ✅ 服务端拒绝第二台 |
| 远程撤销 | ❌ | ✅ 下次心跳即失效 |
| 换机放行 | 必须重新签发 | 运营一条命令解绑 |

---

## 一、启动服务

```bash
tdl license server \
  --db ~/.tdl-license/registry.json \
  --admin-token "$(openssl rand -hex 16)" \
  --addr 0.0.0.0:8964
```

- `--db` 是账本，里面有客户密钥全文，权限 0600，**必须备份**。
- `--admin-token` 是运营接口的凭据。不给则运营接口关闭，只保留激活/校验。
- `--addr` 默认只监听 `127.0.0.1`（配合 cloudflared）；直接对公网时改 `0.0.0.0`
  并加防火墙规则。

启动后会打印客户端接法。

## 二、Cloudflare Tunnel（不需要公网 IP、不开端口）

**可以用，而且是这套服务最合适的暴露方式。** 免费额度足够，TLS 由 Cloudflare 终结。

### 2.1 临时域名（5 分钟试用）

```bash
cloudflared tunnel --url http://127.0.0.1:8964
```

输出里会有一行 `https://xxxx-xxxx-xxxx.trycloudflare.com`。
缺点是每次重启地址都变，只适合验证链路。

### 2.2 固定域名（正式用）

```bash
# 一次性
cloudflared tunnel login
cloudflared tunnel create tdl-license
cloudflared tunnel route dns tdl-license lic.example.com

# 常驻
cloudflared tunnel run --url http://127.0.0.1:8964 tdl-license
```

或写成配置后 `systemd` 托管：

```yaml
# /etc/cloudflared/config.yml
tunnel: <TUNNEL_ID>
credentials-file: /root/.cloudflared/<TUNNEL_ID>.json
ingress:
  - hostname: lic.example.com
    service: http://127.0.0.1:8964
  - service: http_status:404
```

```bash
cloudflared service install
systemctl enable --now cloudflared
```

验证：

```bash
curl https://lic.example.com/healthz
# {"keys":0,"ok":true,"server":"tdl-license"}
```

> 云盾的 WAF 不要拦 `/v1/*`；速率限制放到 Cloudflare 侧更合适（服务端自带的
> 每 IP 30 次/分钟是防密钥爆破的，不是防 DDoS 的）。

## 三、签发与登记

签发和服务是两步：签发只要主密钥（可以离线、可以在另一台机器），登记要账本。
这样「卖密钥的人」和「跑服务器的人」可以分开。

```bash
# 1) 签发
KEY=$(tdl license gen --key-file ~/.tdl-issuer.txt --device CT84B4MD --days 365 | head -1)
echo "$KEY"

# 2) 登记（否则服务端不认这把密钥）
curl -X POST -H "Authorization: Bearer $ADMIN_TOKEN" \
  -d "{\"key\":\"$KEY\",\"kind\":\"short\",\"expiry_day\":365,\"note\":\"客户张三\"}" \
  https://lic.example.com/v1/admit

# 3) 把 KEY 发给客户
```

`--device any` 表示首激绑定：客户不用先报设备码，但一把密钥只能用在一台设备上。

## 四、运营操作

```bash
# 看全部密钥
curl -H "Authorization: Bearer $T" https://lic.example.com/v1/keys

# 撤销（客户跑路/退款）—— 下次心跳即失效
curl -X POST -H "Authorization: Bearer $T" -d '{"key":"KEY"}' https://lic.example.com/v1/revoke

# 解绑（客户换手机）—— 密钥仍有效，可绑到新设备
curl -X POST -H "Authorization: Bearer $T" -d '{"key":"KEY"}' https://lic.example.com/v1/release
```

账本里的 `refusals` 是盗用信号：正常客户不会用同一把密钥反复激活第三台设备。

## 五、客户端接入

### 5.1 命令行（桌面 / Docker）

```bash
tdl license activate --key <密钥> --server https://lic.example.com
```

之后每次启动，若距上次成功校验超过 12 小时，会先向服务端核对一次：

- 服务端说 `revoked` / `expired` → **清除本地激活**，命令被拒；
- 网络不通 → 保留本地激活（客户在飞机上也要能用已买的授权）。

### 5.2 手机 App

激活页会把密钥同时提交给服务端（地址编译进 so），客户不需要填服务器地址：

```bash
# 构建时注入
-X github.com/iyear/tdl/archive.licenceServerDefault=https://lic.example.com
```

### 5.3 Docker 镜像

```bash
make licensed-docker TDL_LICENSE_MASTER_FILE=~/.tdl-issuer.txt
# 或手工
docker build --build-arg LICENSE_HMAC=<hmac> --build-arg LICENSE_PUB=<pub> -t tdl-archive:licensed .
```

容器里再传运行参数：

```bash
tdl archive serve --license-server https://lic.example.com
```

## 六、心跳间隔的取舍

`--license-check` 默认 12 小时（`WebServer.LicenceCheckInterval`）。

| 间隔 | 撤销延迟 | 代价 |
| --- | --- | --- |
| 1 小时 | 快 | 弱网客户启动变慢，服务端请求多 |
| **12 小时（默认）** | **当天收敛** | 平衡 |
| 7 天 | 慢 | 请求少，但撤销形同虚设 |

客户端不会因为网络失败而失效——只有服务端**明确否定**才清除。这条边界很重要：
断网的用户不该被惩罚，被撤销的用户不该被放过。

## 七、安全清单

- [ ] `~/.tdl-issuer.txt`（主密钥）离线备份，不要放进仓库
- [ ] `registry.json`（账本）定期备份，权限 0600
- [ ] `--admin-token` 用随机值，不要复用别处密码
- [ ] Cloudflare 上给 `/v1/*` 配速率规则
- [ ] 正式发行前把 APK 换成自己的签名并保管好 keystore（**换签名会改变设备码，
      所有已激活客户都需要重新激活**）

## A.1 线上地址

| 项 | 值 |
| --- | --- |
| 公网入口 | `https://lic.emoe.eu.cc` （Cloudflare 代理，自动 TLS） |
| 源站 | `127.0.0.1:8964`（只监听回环，公网只能经隧道进来） |
| Cloudflare 账号 | `ed1957935f0efde06a68432e5fc48d97` |
| Zone | `emoe.eu.cc` = `8ae276aa463633def4bf48699027681f` |
| Tunnel | `tdl-license` = `cbe5f1c3-9ede-475b-8f9e-bd2a31661ba8` |
| DNS | `lic` CNAME → `cbe5f1c3-9ede-475b-8f9e-bd2a31661ba8.cfargotunnel.com`，proxied |

创建命令（已执行，换账号时照此重做）：

```bash
API=https://api.cloudflare.com/client/v4
curl -X POST "$API/accounts/$CF_ACCOUNT_ID/cfd_tunnel" \
  -H "Authorization: Bearer $CF_API_TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"tdl-license","config_src":"cloudflare"}'
# 用返回的 token 和 service 建 ingress
curl -X PUT "$API/accounts/$CF_ACCOUNT_ID/cfd_tunnel/$TID/configurations" \
  -H "Authorization: Bearer $CF_API_TOKEN" -H 'Content-Type: application/json' \
  -d '{"config":{"ingress":[{"hostname":"lic.emoe.eu.cc","service":"http://127.0.0.1:8964"},{"service":"http_status:404"}]}}'
curl -X POST "$API/zones/$ZONE_ID/dns_records" \
  -H "Authorization: Bearer $CF_API_TOKEN" -H 'Content-Type: application/json' \
  -d '{"type":"CNAME","name":"lic","content":"<TID>.cfargotunnel.com","proxied":true,"ttl":1}'
```

## A.2 常驻方式（systemd 用户级）

| 单元 | 作用 |
| --- | --- |
| `tdl-license.service` | 授权服务，`Restart=always` |
| `tdl-tunnel.service` | cloudflared 隧道，`Restart=always`，依赖上一个 |

```bash
systemctl --user status  tdl-license tdl-tunnel
systemctl --user restart tdl-license   # 改完账本/换二进制后
journalctl --user -u tdl-license -f
loginctl enable-linger $USER           # 已开启：开机即起，不需要登录
```

凭据文件（均 0600）：

```
~/.cloudflare/cf.env          API token / R2 密钥
~/.cloudflare/tunnel.env      tunnel id + token + 域名
~/.tdl-license/admin.env      ADMIN_TOKEN
~/.tdl-license/registry.json  账本
```

## A.3 签发的一步不漏流程

**关键点：`gen` 只做签名，`admit` 才把它写进服务端白名单。少一步，激活会返回
`unknown_key`。** 这是故意的——能签名的只有你，能放行的也只有你。

```bash
# 1) 客户在激活页看到设备码，发给你
DEV=CT84B4MD

# 2) 本地签发（私钥不出本机）
KEY=$(./tdl license gen --key-file ~/.tdl-issuer.txt --device $DEV --days 365 | head -1)
#   永久： --forever    强密钥： --strong（127 字符，只能粘贴）

# 3) 登记到服务端（否则服务端不认）
curl -s -X POST https://lic.emoe.eu.cc/v1/admit \
  -H "Authorization: Bearer $(sed -n 's/^ADMIN_TOKEN=//p' ~/.tdl-license/admin.env)" \
  -H 'Content-Type: application/json' \
  -d "{\"key\":\"$KEY\",\"kind\":\"short\",\"expiry_day\":365,\"note\":\"客户名/订单号\"}"

# 4) 把 $KEY 发给客户
```

`expiry_day` 是**天数**，`0` 表示永久。

## A.4 运营动作（全部走公网，不需要登录服务器）

```bash
TOK=$(sed -n 's/^ADMIN_TOKEN=//p' ~/.tdl-license/admin.env)
S=https://lic.emoe.eu.cc
H=(-H "Authorization: Bearer $TOK" -H 'Content-Type: application/json')

curl -s "${H[@]}" $S/v1/keys | jq          # 全部记录：绑定设备/最后心跳/拒绝次数
curl -s "${H[@]}" -X POST $S/v1/revoke  -d '{"key":"<KEY>"}'   # 撤销：下次心跳即踢出
curl -s "${H[@]}" -X POST $S/v1/release -d '{"key":"<KEY>"}'   # 解绑：客户换手机
```

`refusals` 是盗用信号：同一把密钥被拿去激活第二台设备时会 +1。

## A.5 实测记录（真机 PJE110 / Android，包名 com.tdl.archive.app）

| # | 动作 | 结果 |
| --- | --- | --- |
| 1 | 未激活启动 | 只出激活页，业务接口全 402 |
| 2 | 经 `https://lic.emoe.eu.cc` 激活 | 200，服务端落 `device=CT84B4MD`，剩余 364 天 |
| 3 | 杀进程重启 | 保持激活（画面字节级一致） |
| 4 | 同一密钥换设备码 `ZZZZZZZZ` | 403 `bound_elsewhere`，`refusals` +1 |
| 5 | 把本地 `last_check` 归零强制心跳 | 服务端 `last_seen` 更新 → 心跳链路通 |
| 6 | 远程 `revoke` 后再启动 | 本地 `activation.json` 被删除，踢回激活页 |
| 7 | 新密钥重新激活 | 恢复主界面 |

## A.6 已知边界

- **Docker 镜像未实机构建**：本机无 docker daemon，只验证了 `Dockerfile` 的
  `LICENSE_SERVER` 参数与 `make licensed-docker` 的参数传递，没有产出镜像。
- **`--device any` 在 root 机上可换机**：绑定写在签名里，`any` 没有绑定字段，
  改本地文件即可搬走。要真正一机一码，每个客户都问设备码。
- **短密钥挡的是随手编和改字符，不是专业逆向**：能从 apk 里挖出校验串就能自签。
  高价值客户用 `--strong`。
- **换签名会改设备码**，已激活客户需要重新激活；正式发货前定好 keystore。
